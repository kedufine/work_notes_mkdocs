# 인수인계 자료 변환·등록

인수인계 자료 원본을 빠짐없이 읽어 MkDocs 문서로 옮기는 절차입니다. 원본은 폴더 구조가 정리되어 있지 않고 파일 수가 많을 수 있으므로, **기계적 변환(1단계)과 주제별 정리·등록(2단계)을 분리**하고 모든 진행 상태를 `manifest.json`에 기록합니다.

문서 본문의 작성 규칙(제목 구조, 표, 알림 상자, `nav`, 홈 갱신, 빌드 검증)은 `.agents/skills/mkdocs-writing-guide/SKILL.md`를 따릅니다. 이 스킬은 그 규칙 위에서 인수인계 자료에만 해당하는 절차를 정합니다.

---

## 1. 폴더와 산출물

| 경로 | 역할 | Git |
| :--- | :--- | :--- |
| `1. RAW/` (또는 `1. 인수인계 자료 원본/`) | 사용자가 받은 인수인계 건별 원본 폴더(예: `2024년 조호재 인수인계 자료/`, `2025년 김철수 인수인계 자료/`)가 들어오는 곳입니다. **에이전트는 이 폴더의 파일을 수정·이동·삭제하지 않습니다.** | 제외 |
| `2. 변환 중간본/` | 1단계 스크립트가 만드는 원문 마크다운, `manifest.json`, `변환 보고서.md`입니다. 언제든 다시 만들 수 있습니다. | 제외 |
| `mkdocs/docs/handover/` | 2단계에서 정리한 인수인계 공개용 문서 아카이브입니다. **마스터 허브(`index.md`)와 건별 독립 폴더(`handover/<건별-슬러그>/`)**로 구성됩니다. | 포함 |

원본과 중간본은 대용량 파일이고 언제든 다시 만들 수 있으므로 `.gitignore`로 제외합니다. 사이트는 사용자 본인만 로컬에서 보는 용도이므로, **개인정보(연락처, 이름 등)를 가리지 않고 원문 그대로 옮깁니다.**

## 2. 사전 점검

작업을 시작할 때마다 먼저 도구를 확인합니다.

```bash
.venv/bin/python .agents/skills/handover-to-mkdocs/scripts/convert.py --check       # macOS
.venv\Scripts\python .agents\skills\handover-to-mkdocs\scripts\convert.py --check   # Windows
```

이 문서의 이후 명령은 macOS 경로로 적습니다. Windows에서는 `.venv\Scripts\python`과 `\` 경로 구분자를 사용합니다. 변환 스크립트는 표준 라이브러리만 쓰므로, `.venv`가 아직 없으면 `--check`는 시스템 파이썬(`python3`, Windows는 `py`)으로 실행합니다.

사용자 PC에는 **아무 프로그램도 설치되어 있지 않을 수 있다**고 가정합니다. 문서 사이트는 `.venv`에 설치된 Python, MkDocs, Material for MkDocs(`mkdocs-material`)가 있어야 빌드·실행되고, 변환은 Node.js, kordoc, OfficeCLI가 있어야 합니다. `--check`는 이 여섯 항목(`python`, `mkdocs`, `mkdocs-material`, `node`, `kordoc`, `officecli`)을 모두 확인합니다.

- 여섯 항목 가운데 `없음`이 하나라도 있으면, 사용자에게 알린 뒤 설치 스크립트를 실행합니다. 설치 스크립트는 없는 프로그램만 설치합니다.
- 시스템 파이썬도 없어서 `--check`를 실행할 수 없으면(`python3`·`py`를 찾을 수 없음, 또는 Windows에서 `python`을 입력하면 Microsoft Store가 열림), 확인을 건너뛰고 바로 설치 스크립트를 실행합니다. 설치 스크립트가 파이썬부터 설치합니다.

- macOS: `bash setup/setup-mac.sh`
- Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File setup\setup-windows.ps1` (`-Pause`는 넘기지 않습니다. 넘기면 끝에서 Enter 입력을 기다리며 멈춥니다.)

에이전트가 대신할 수 없는 일(macOS에서 Homebrew 설치에 필요한 암호 입력, Windows의 사용자 계정 컨트롤 승인·Microsoft Store 설치, 인터넷 연결 문제)을 만나면, 설치 스크립트가 `[사용자 조치 필요]` 안내를 출력하고 종료 코드 3으로 끝납니다. 이때는 `AGENTS.md`의 "사용자 조치 절차"대로 안내를 그대로 전달하고 멈춘 뒤, 사용자가 "했어"라고 하면 같은 명령을 다시 실행해 이어서 진행합니다. Windows 설치 스크립트를 실행하기 전에는 UAC 창이 뜰 수 있다고 먼저 알립니다.

설치 스크립트가 실패하면 `README.md` 2절(수동 설치)의 해당 단계를 따릅니다. kordoc을 직접 설치할 때는 OCR 엔진이 빠지지 않도록 `npm install -g kordoc --allow-scripts=onnxruntime-node,protobufjs`를 사용합니다. 원문 안내는 <https://github.com/chrisryugj/kordoc>, <https://github.com/iOfficeAI/OfficeCLI>에 있습니다. 설치 뒤에도 `없음`이 나오면 새 터미널에서 다시 확인합니다.

## 3. 1단계: 원본 전체를 중간본으로 변환

```bash
.venv/bin/python .agents/skills/handover-to-mkdocs/scripts/convert.py --dry-run   # 대상 목록과 처리 경로만 확인
.venv/bin/python .agents/skills/handover-to-mkdocs/scripts/convert.py             # 변환 실행
```

스크립트는 원본 폴더를 하위 폴더까지 모두 훑고, 형식에 따라 다음 도구로 변환합니다.

| 형식 | 도구 | 비고 |
| :--- | :--- | :--- |
| `.hwp` `.hwpx` `.hwpml` `.hml` | kordoc | 표·병합 셀 보존 |
| `.pdf` | kordoc | 스캔 PDF(`IMAGE_BASED_PDF`)는 OCR을 켜고 자동 재시도 |
| `.docx` `.xlsx` | kordoc → 실패 시 OfficeCLI | |
| `.xls` `.docm` `.xlsm` | kordoc | |
| `.pptx` | OfficeCLI | kordoc은 PPTX를 지원하지 않음. 슬라이드별 `## 슬라이드 N` 제목으로 변환 |
| `.png` `.jpg` `.jpeg` `.webp` | kordoc | 내장 OCR |
| `.txt` `.md` `.csv` `.tsv` | 스크립트 | UTF-8·CP949 자동 판별, CSV는 표로 변환(최대 500행) |
| `.doc` `.ppt` `.rtf`, 압축 파일 등 | 변환 안 함 | 보고서에 조치 방법(다시 저장, 압축 해제)을 기록 |

- `~$`로 시작하는 Office 잠금 파일, 숨김 파일, `Thumbs.db`, `desktop.ini`는 제외합니다.
- 중간본은 `2. 변환 중간본/<8자리 ID>_<원본 파일명>.md`로 평탄하게 저장합니다. ID는 원본 상대 경로의 해시이므로 같은 파일은 항상 같은 ID를 받습니다. kordoc이 추출한 그림은 `2. 변환 중간본/images/<중간본 이름>/`에 저장됩니다.
- 원본 해시가 바뀌지 않은 파일은 다시 변환하지 않습니다. 중간에 끊겨도 같은 명령을 다시 실행하면 이어서 진행됩니다. 실패한 파일은 매번 다시 시도합니다.
- 파일이 많으면 명령을 백그라운드로 실행하고 끝날 때까지 기다립니다. 진행 중에 파일을 하나씩 따로 변환하지 않습니다.

### 3.1 manifest.json 필드

최상위에는 `version`, `updated_at`(마지막 실행 시각), `tools`(도구 버전), `files`(원본 ID → 항목)가 있습니다. 각 항목의 필드는 다음과 같습니다.

| 필드 | 뜻 |
| :--- | :--- |
| `id` | 원본 상대 경로의 해시 8자리. `files`의 키와 같습니다. |
| `source`, `ext`, `size`, `sha256` | 원본 폴더 기준 상대 경로(NFC), 확장자, 크기, 내용 해시 |
| `status` | `converted`, `empty`, `failed`, `unsupported`, `removed` |
| `tool`, `error_code`, `error`, `hint` | 사용한 도구, 실패 코드, 오류 원문, 조치 방법 |
| `output`, `images`, `chars` | 중간본 파일명, 그림 폴더(`2. 변환 중간본/` 기준), 중간본 글자 수 |
| `ocr` | 스캔 PDF라서 OCR로 다시 변환했으면 `true` |
| `modified` | 원본 파일의 수정일 |
| `published` | 이 원본을 반영한 MkDocs 문서 경로 목록(**2단계에서 에이전트가 기록**, `handover/<건별-슬러그>/...md`) |
| `needs_republish` | 원본이 바뀌거나 삭제되어 문서를 고쳐야 하면 `true`(**반영 후 에이전트가 `false`로 변경**) |

스크립트는 재실행해도 `published`와 `needs_republish`를 보존합니다. 에이전트가 고치는 필드는 이 두 개뿐입니다.

### 3.2 변환 결과 점검

`2. 변환 중간본/변환 보고서.md`를 읽고 다음을 사용자에게 보고합니다.

- 상태별 개수와 **조치가 필요한 파일**(실패, 미지원, 빈 결과) 목록과 조치 방법
- 사용자가 조치할 수 있는 항목(암호 해제, `.doc`→`.docx` 다시 저장, 압축 해제)이 있으면 조치 후 1단계를 다시 실행하도록 안내합니다. 이 항목 때문에 2단계를 멈추지는 않습니다.

## 4. 2단계: 주제별 정리와 MkDocs 등록 (다수 인수인계 건 지원)

인수인계 문서는 단일 건이 아니며 최대 수십 개가 사이트에 누적될 수 있습니다. 따라서 **모든 인수인계 문서는 건별로 전용 디렉터리에 격리하여 관리하고, 화면 메뉴(nav)에서도 건별 섹션으로 분리**해야 합니다.

### 4.0 인수인계 건(Package) 식별 및 영문 슬러그 규칙

1. `1. RAW/` 바로 아래의 최상위 폴더가 개별 인수인계 건(패키지)의 단위입니다 (예: `1. RAW/2024년 조호재 인수인계 자료/`).
2. 폴더명에서 **기준 연도, 담당자명, 핵심 주제**를 파악하여 영문 소문자·숫자·하이픈 조합의 고유 슬러그를 만듭니다.
    - 규칙: `YYYY-<person-name>` 또는 `YYYY-<person-name>-<topic>` (예: `2024-cho-hojae`)
3. **폴더명 오타 및 기준 연도 검증**:
    - 사용자 원본 폴더명에 오타(예: `2004년 조호재 인수인계 자료`와 같이 2024년이 오기된 경우)가 있거나 기준 연도가 불명확할 때는, 원본 파일들의 작성일·수정일 및 내부 문서 본문(예: 2023년 말 협의 결과, 2024년 사업 계획 등)을 대조하여 실제 기준 연도를 판별합니다.
    - 오타가 포함된 슬러그나 메뉴명을 쓰지 않고 올바른 실제 연도 슬러그(예: `2024-cho-hojae`)와 nav 한글 명칭(`2024년 조호재`)을 부여합니다.
4. 문서는 반드시 `mkdocs/docs/handover/<건별-슬러그>/` 아래에 배치합니다. `handover/` 루트에 특정 건의 대분류 폴더(`overview/`, `voc/` 등)를 직접 두지 않습니다.

### 4.1 건별 내부 분류 설계

1. 해당 인수인계 건의 `manifest.json` 내 `source` 파일들을 훑어 업무 주제를 파악합니다.
2. 건별 대분류는 3~8개로 정합니다(예: `overview/`, `voc/`, `records/`, `tasks/` 등).
3. 분류안(대분류 이름, 영문 폴더명, 문서 수)을 사용자에게 제시하고 작업을 이어갑니다.

### 4.2 문서 단위 결정 및 연관 원본 통합 원칙

- 기본은 **원본 파일 1개 → 문서 1개**이지만, **동일한 업무 맥락이나 하나의 민원·사안에 얽힌 연관 원본들은 단일 문서로 유기적으로 통합**하여 실무 활용 가치를 극대화합니다:
    - **질의-회신 쌍**: 사용자의 질의 원문(`질의.txt`)과 고객센터 회신 공문(`...답변.hwp`)
    - **판본 및 검토 이력**: 초안(`...초안.hwp`), 구버전(`old/...`), 최종안(`..._F.hwp`)
    - **협의 이력 및 증빙**: 실무자 메신저 캡처본(`KakaoTalk_...jpg`), 협의 내용 정리 텍스트(`...txt`), 과거 관련 협의회 안건
    - **절차 매뉴얼 및 실행 코드**: 매뉴얼 슬라이드(`...매뉴얼.pptx`) + 실행 쿼리(`...종료(쿼리).sql`)
- **통합 문서 표기 및 추적 규칙**:
    - `## 요약` 표의 `**원본 경로**`에는 사안을 대표하는 핵심 최종본 1건의 경로를 적습니다.
    - `## 요약` 표의 `**함께 반영한 판본**` 행에 통합된 모든 연관 원본의 상대 경로와 수정일을 빠짐없이 열거합니다.
    - `manifest.json`에서 통합에 포함된 모든 원본 항목의 `published` 필드에 해당 통합 문서의 경로를 동일하게 등록하여 추적 누락을 원천 방지합니다.
- **미지원 형식(SQL, 스크립트 등) 및 인코딩 주의사항**:
    - 공공기관 및 Windows 환경에서 작성된 스크립트·SQL 파일은 종종 **`UTF-16LE`(BOM 포함) 또는 `CP949`**로 인코딩되어 일반 텍스트 읽기에서 실패하거나 바이너리로 취급될 수 있습니다.
    - Python 스크립트(`open(..., encoding='utf-16le', errors='replace')`) 등으로 내용을 정확히 확인한 후, 관련 절차/매뉴얼 문서의 코드 블록(` ```sql `, ` ```bash `)으로 전문을 누락 없이 수록하여 원본 손실을 방지합니다.
- **전수 추적 원칙**:
    - 내용이 거의 없는 파일(양식 빈칸, 메모 등)도 관련 문서나 `기타 자료`에 통합 수록하여, 모든 `converted`·`empty` 및 텍스트 확인 가능한 `unsupported` 원본이 최소 한 문서의 `published`에 포함되어야 합니다.

### 4.3 문서 작성 및 경로 규칙

- **문서 파일 경로**: `mkdocs/docs/handover/<건별-슬러그>/<대분류 영문>/<영문 소문자-하이픈>.md`
- **전용 이미지 경로 및 포맷 변환 (필수)**:
    - 경로: `mkdocs/docs/handover/<건별-슬러그>/<대분류>/images/<문서 파일명>/`
    - **BMP 포맷의 PNG 변환**: HWP/HWPX 문서에서 추출된 이미지가 `.bmp` 포맷인 경우, 웹 브라우저(Chrome, Safari 등)에서 정상 렌더링되지 않거나 용량(장당 수 MB)으로 인해 로딩이 지연됩니다. 전용 폴더로 이전할 때 반드시 **Pillow(PIL) 라이브러리를 사용하여 `.png`로 변환**하여 저장하고 마크다운 본문에도 `.png` 확장자로 링크합니다.
    - **불필요한 공문 직인/로고 제외**: 공문서 하단에 관행적으로 반복 첨부되는 기관 직인/도장/로고(예: KERIS 직인 `image_001.png` 등 22KB 내외 동일 이미지)는 사이트 가독성을 위해 이전 대상에서 제외하고, 본문 이해에 필수적인 **시스템 UI 캡처 화면만 선별 이전**합니다.
- **골격**: `mkdocs-writing-guide` 4.2절 **인수인계 변환 문서 골격** 준수 (H1 단일 기입, 작성일 명시, 본문 원문 보존, 독립된 `## 인수인계 확인 사항`). **원본 정보(경로, 형식·수정일, 함께 반영한 판본)는 별도 박스(admonition)를 쓰지 않고 반드시 `## 요약` 표 내 행으로 포함**하여 메타데이터를 단일 표로 일원화합니다.
- **네비게이션(`nav`) 등록**:
    - `인수인계` 탭의 첫 항목은 항상 마스터 허브인 `handover/index.md`입니다.
    - 그 아래에 각 인수인계 건별로 독립 섹션을 둡니다.
    - **좌측 메뉴 폭 제한 및 한 줄 표시 규칙 (필수)**: 좌측 사이드바 메뉴는 폭이 제한되어 있어 글자 수가 길어지면 두 줄로 줄바꿈되어 보기에 좋지 않습니다. 따라서 섹션명에 부서나 업무명(예: `(K-에듀파인 업무관리)`)을 덧붙이지 않고, 반드시 **`YYYY년 <담당자명>`** (예: `2024년 조호재`, `2025년 홍길동`) 형태로 간결하게 지정합니다. 소관 업무 및 부서 등의 상세 정보는 해당 건의 개요 페이지(`index.md`) 및 마스터 허브 표에서 충분히 확인하도록 합니다.
    - `navigation.indexes` 설정에 따라 건별 섹션의 첫 항목으로 건별 개요(`handover/<건별-슬러그>/index.md`)를 제목 없이 지정합니다.

```yaml
nav:
  - 홈: index.md
  - 인수인계:
      - handover/index.md # 마스터 허브 (전체 인수인계 목록)
      - 2024년 조호재: # 'YYYY년 이름' 형식으로 간결하게 지정 (두 줄 줄바꿈 방지)
          - handover/2024-cho-hojae/index.md # 건별 개요
          - 업무 개요:
              - K-에듀파인 업무관리 인수인계서: handover/2024-cho-hojae/overview/k-edufine-handover.md
          - 민원·현안 대응:
              - 재배부요청 기능 복구 문의 회신: handover/2024-cho-hojae/voc/redistribution-inquiry-230908.md
          - 기록관리 연계·지침:
              - 2024년 기록물관리 지침 개정 계획: handover/2024-cho-hojae/records/records-guideline-2024.md
          - 단위과제 관리:
              - 공통단위과제 종료 매뉴얼 및 SQL 절차: handover/2024-cho-hojae/tasks/common-task-termination-manual.md
      - 2025년 홍길동: # 향후 추가 건 예시
          - handover/2025-hong-gildong/index.md
          - ...
```

### 4.4 마스터 허브와 건별 개요 페이지의 이원화

1. **마스터 허브 페이지 (`mkdocs/docs/handover/index.md`)**:
    - 사이트의 모든 인수인계 건을 총괄 안내하는 포털 페이지입니다.
    - `## 요약`: 전체 인수인계 패키지 목록 표 (인수인계 건명, 담당자/부서, 소관 업무/시스템, 기준 연월, 수록 문서 수, 상태, 건별 개요 바로가기 링크).
    - `## 1. 등록된 인수인계 건별 안내`: 각 건의 개요, 주요 포함 분야, 바로가기 링크.
    - `## 2. 전체 인수인계 아카이브 현황`: 총 등록 건수, 문서 수, 원본 파일 통계.
    - `## 3. 인수인계 자료 탐색 및 신규 등록 가이드`: 사이드바 탐색 및 추가 절차 안내.
2. **건별 개요 페이지 (`mkdocs/docs/handover/<건별-슬러그>/index.md`)**:
    - 해당 건에 속한 원본과 문서를 전수 추적하는 상세 페이지입니다.
    - `## 요약`: 해당 건의 대분류, 문서 수, 주요 내용 표.
    - `## 1. 원본 현황`: 해당 건의 원본 수, 변환 완료·미지원·실패 건수, 변환 일시.
    - `## 2. 대분류별 문서 목록`: 해당 건 내부의 대분류별 세부 문서 링크.
    - `## 3. 원본 파일 대응표`: 해당 건 원본 경로 → 변환 문서 매핑 전체 표.
    - `## 4. 인수인계 확인 사항 종합`: 해당 건의 일정, 관련 부서, 미결 과제 종합.

### 4.5 홈(`mkdocs/docs/index.md`) 갱신 규칙

- 홈 최상단 `## 요약` 표에는 `인수인계 자료` 항목으로 마스터 허브(`handover/index.md`)를 1행으로 연결합니다.
- `## 1. 최근 업데이트` 표에는 인수인계 건이 추가·갱신될 때마다 **건별로 1행**씩 등록합니다 (예: `[2024년] 조호재 인수인계 자료 (문서 12건)` -> `[문서 열기](handover/2024-cho-hojae/index.md)`). 수십 개 건이 누적되어도 홈 표의 가독성을 유지합니다.

### 4.6 manifest 일괄 갱신 가이드

- 각 원본의 `published` 필드에는 건별 슬러그가 포함된 전체 상대 경로(`handover/<건별-슬러그>/<대분류>/<문서명>.md`)를 배열로 기록합니다.
- 반영 완료 후 `needs_republish`를 `false`로 설정합니다.
- **배치 자동화 팁**: 수십 개 파일의 매핑을 수작업으로 수정하면 누락이 발생하기 쉬우므로, Python 스크립트로 파일 ID와 문서 경로 딕셔너리를 구성하여 일괄 업데이트합니다:
    ```python
    import json
    with open('2. 변환 중간본/manifest.json', 'r', encoding='utf-8') as f:
        data = json.load(f)
    mapping = {'<file-id>': ['handover/<건별-슬러그>/<대분류>/<문서명>.md'], ...}
    for fid, entry in data['files'].items():
        if fid in mapping:
            entry['published'] = mapping[fid]
            entry['needs_republish'] = False
    with open('2. 변환 중간본/manifest.json', 'w', encoding='utf-8') as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
    ```

## 5. 원본이 바뀌었을 때 (증분 갱신)

1. `convert.py`를 다시 실행합니다. 새 파일만 변환되고, 바뀐 파일은 재변환되며, 삭제된 파일은 `removed`로 표시됩니다.
2. 새 파일이 속한 인수인계 건의 슬러그 디렉터리(`handover/<건별-슬러그>/`) 하위 분류에 문서를 추가하거나 기존 문서에 통합합니다.
3. 완전히 새로운 인수인계 건(새 상위 폴더)이 들어온 경우:
    - 새 건별 슬러그 디렉터리 생성 및 문서 작성
    - 새 건별 `index.md` 작성
    - `mkdocs.yml`의 `nav`에 새 인수인계 건 섹션 추가
    - 마스터 허브(`handover/index.md`) 표에 새 건 행 추가
    - 홈(`index.md`) 최근 업데이트 표 갱신
4. 해당 건의 개요 페이지 및 `manifest.json`을 갱신하고 빌드 검증을 수행합니다.
