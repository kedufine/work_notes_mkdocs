# 업무인수인계 질문지 작성·답변 반영

인계자가 남긴 자료만으로는 업무를 이어받기 어려운 부분을 인계자에게 직접 물어서 문서를 보강하는 절차입니다. `AGENTS.md`의 처리 과정 가운데 **3단계(질문지 작성)와 4단계(답변 반영)**를 정합니다. 1단계와 2단계는 `.agents/skills/handover-to-mkdocs/SKILL.md`에 있습니다.

이 스킬은 **무엇을 묻고, 답변을 어디에 어떻게 반영하는지**를 정합니다. 문서에 넣는 형식은 `.agents/skills/mkdocs-writing-guide/SKILL.md` 4.2·4.3절을 따릅니다.

---

## 1. 폴더와 스크립트

| 경로 | 역할 | Git |
| :--- | :--- | :--- |
| `3. 업무인수인계 질문지/` | 질문지 엑셀 파일과 인계자가 회신한 파일을 두는 곳입니다. 에이전트는 **새 질문지를 만들기만 하고, 이미 있는 파일을 수정·이동·삭제하지 않습니다.** | 제외 |

- 보강하는 대상은 건별 통합 문서(`mkdocs/docs/handover/<건별-슬러그>/index.md`)입니다.
- 질문지는 `scripts/questionnaire.py`로 만들고 읽습니다. 표준 라이브러리만 사용하므로 `.venv`의 파이썬만 있으면 실행됩니다. 이 문서의 명령은 macOS 경로로 적으며, Windows에서는 `.venv/Scripts/python`을 사용합니다.

## 2. 3단계: 질문지 작성

### 2.1 시작 조건

- 해당 인수인계 건의 2단계가 끝나서 통합 문서가 등록되어 있어야 합니다. 끝나지 않았다면 `handover-to-mkdocs`의 1·2단계를 먼저 수행합니다.
- 질문지는 인수인계 건 단위로 만듭니다. 한 번에 여러 건을 등록했다면 인계자별로 질문지를 따로 만듭니다.

### 2.2 질문을 뽑는 기준

해당 건의 통합 문서(특히 본문의 `확인 필요` 표시와 `인수인계 확인 사항`의 미결 사항)와 중간본을 다시 읽으면서, 아래 유형에 해당하는 부분을 찾습니다. 인수자가 문서를 읽고 실제로 업무를 수행한다고 가정했을 때 막히는 지점이 질문 대상입니다. `질문 유형` 열에는 이 표의 유형 이름을 적습니다.

| 질문 유형 | 찾는 부분 | 질문 예시 |
| :--- | :--- | :--- |
| 절차·방법 | 결과만 적혀 있고 수행 순서, 메뉴 경로, 입력값이 없는 업무 | "○○ 일괄 종료는 어느 메뉴에서 어떤 순서로 실행합니까?" |
| 담당·연락처 | "담당자에게 요청", "관련 부서와 협의"처럼 상대가 특정되지 않은 표현 | "협의 대상 부서와 담당 역할, 연락처를 알려 주시겠습니까?" |
| 일정·기한 | 주기나 마감일이 빠진 반복 업무, "연초", "추후"와 같은 모호한 시점 | "매년 몇 월에 시작하며 제출 마감일은 언제입니까?" |
| 시스템·권한 | 접속 주소, 계정, 권한 신청 절차, 설치 프로그램이 빠진 시스템 업무 | "관리자 권한은 어느 부서에 어떤 양식으로 신청합니까?" |
| 진행 중·미결 | "검토 중", "협의 예정", "추후 결정"으로 끝난 사안의 현재 상태와 다음 조치 | "이 사안은 현재 어디까지 진행되었고, 다음에 할 일은 무엇입니까?" |
| 판단 기준·예외 | 문서에 적히지 않은 처리 기준, 자주 발생하는 예외와 대응 방법 | "반려하는 기준이 있습니까? 자주 들어오는 예외 요청은 무엇입니까?" |
| 자료 누락 | 본문에서 언급되지만 받지 못한 파일, 사용자가 조치할 수 없어 변환하지 못한 파일(인계자만 아는 암호 등), 내용이 비어 있는 양식 | "'붙임 2 세부 일정표'를 받지 못했습니다. 파일을 보내 주실 수 있습니까?" |
| 용어·약어 | 설명 없이 쓰인 내부 용어, 약어, 시스템 별칭 | "'재배부'는 구체적으로 어떤 처리를 가리킵니까?" |
| 자료 간 불일치 | 문서끼리 날짜·수치·담당이 서로 다른 부분, 최신본이 무엇인지 알 수 없는 판본 | "두 문서의 마감일이 다릅니다. 어느 쪽이 현재 기준입니까?" |

중요도는 다음 기준으로 정합니다.

| 중요도 | 기준 |
| :---: | :--- |
| 상 | 답을 모르면 업무를 시작하거나 기한을 지킬 수 없는 사항(임박한 일정, 접속·권한, 진행 중인 사안의 다음 조치) |
| 중 | 업무를 수행할 수는 있으나, 모르면 시행착오가 생기는 사항(세부 절차, 담당 부서, 판단 기준) |
| 하 | 배경을 이해하는 데 도움이 되는 사항(용어, 과거 경위) |

### 2.3 질문 작성 규칙

- **자료에서 답을 찾을 수 있는 질문은 넣지 않습니다.** 질문을 확정하기 전에 해당 건의 중간본 전체에서 관련 키워드를 검색하여, 다른 파일에 답이 있는지 확인합니다. 답이 있으면 질문하지 않고 통합 문서의 해당 절에 반영합니다.
- **질문 하나에는 한 가지만 묻습니다.** 여러 가지를 한꺼번에 물으면 일부만 답변이 돌아옵니다.
- **근거를 함께 적습니다.** `관련 자료`에는 원본 파일의 경로(건 폴더 기준 상대 경로)를, `관련 내용`에는 해당 위치와 원문 구절을 적어서 인계자가 어느 부분에 관한 질문인지 바로 알 수 있게 합니다. 특정 자료에 근거하지 않는 질문(예: 자료에 없는 업무가 더 있는지)은 두 칸을 비우고 `업무 분야`만 적습니다.
- **원하는 답변의 형태를 알려 줍니다.** "담당자를 알려 주세요"보다 "부서명, 담당 역할, 내선 번호를 알려 주시겠습니까?"가 더 정확한 답변을 받습니다. "예/아니요"로만 답하게 되는 질문은 피합니다.
- **인계자가 읽는 글이므로 정중한 문장으로 씁니다.** 자료의 부족함을 지적하는 표현("누락되어 있음", "설명이 부실함")은 쓰지 않습니다.
- **인계자의 부담을 고려합니다.** 같은 내용을 묻는 질문은 하나로 합치고, 한 건의 질문이 40개를 넘으면 중요도 '하'부터 줄입니다. 줄인 항목은 통합 문서에 `확인 필요`와 `**미결 사항**`으로 그대로 남기고, 사용자에게 줄인 항목을 보고합니다. 반대로 질문할 것이 없는데 개수를 채우려고 만들지 않습니다.
- 질문은 업무 분야(통합 문서의 업무별 절)별로 묶고, 같은 분야 안에서는 중요도 '상'부터 배치합니다.
- 마지막 질문으로 "인수인계 자료에 적지 못했지만 후임자가 알아야 할 업무나 주의 사항이 있으면 알려 주시겠습니까?"를 넣어서, 자료에 드러나지 않은 업무를 확인합니다.

### 2.4 질문 목록 작성과 엑셀 생성

질문 목록을 `2. 변환 중간본/질문지/<건별-슬러그>.json`에 다음 형식으로 저장합니다.

```json
{
  "package": "2024-cho-hojae",
  "handover_from": "조호재",
  "handover_to": "",
  "date": "2026-10-12",
  "due": "",
  "questions": [
    {
      "category": "단위과제 관리",
      "source": "별첨자료/공통단위과제 종료 매뉴얼.pptx",
      "context": "슬라이드 3 \"쿼리 실행 후 담당자에게 통보\"",
      "question": "통보 대상의 부서명, 담당 역할, 연락처를 알려 주시겠습니까?",
      "type": "담당·연락처",
      "priority": "상",
      "doc": "handover/2024-cho-hojae/index.md > 3.1 공통단위과제 종료"
    }
  ]
}
```

| 필드 | 뜻 |
| :--- | :--- |
| `package` | 건별 슬러그. 질문지의 `안내` 시트에 기록됩니다. |
| `handover_from` | 인계자 이름(필수). 파일명에 들어갑니다. `handover-to-mkdocs` 4.0절에서 확인한 담당자명을 씁니다. |
| `handover_to`, `due` | 인수자 이름과 회신 요청일. 사용자가 알려 준 경우에만 적고, 모르면 빈 문자열로 둡니다. |
| `date` | 질문지 작성일(`YYYY-MM-DD`). 생략하면 오늘 날짜입니다. 파일명의 `YYMMDD`가 됩니다. |
| `questions[].doc` | 답변을 반영할 위치. 통합 문서의 경로 뒤에 ` > 절 번호와 제목`을 붙입니다. 특정 절에 해당하지 않으면 경로만 적습니다. |
| `questions[].priority` | `상`, `중`, `하` 가운데 하나. 생략하면 `중`입니다. |

번호(`Q-001`부터)는 스크립트가 목록 순서대로 붙입니다. 그다음 엑셀을 만듭니다.

```bash
.venv/bin/python .agents/skills/handover-questionnaire/scripts/questionnaire.py build \
  --spec "2. 변환 중간본/질문지/2024-cho-hojae.json"
```

- 결과 파일은 `3. 업무인수인계 질문지/YYMMDD <인계자명> 업무인계인수 질문지.xlsx`입니다(예: `261012 조호재 업무인계인수 질문지.xlsx`). 이 파일명 형식은 바꾸지 않습니다.
- 파일에는 작성 방법을 적은 `안내` 시트와 `질문지` 시트가 들어 있습니다. `질문지` 시트의 열은 `번호`, `업무 분야`, `관련 자료`, `관련 내용`, `질문`, `질문 유형`, `중요도`, `답변`, `참고 자료·비고`, `반영 문서`이며, 인계자는 노란색 칸인 `답변`과 `참고 자료·비고`만 작성합니다.
- **같은 이름의 파일이 이미 있으면 스크립트가 덮어쓰지 않고 종료 코드 1로 끝납니다.** 그 파일은 사용자가 이미 인계자에게 보냈을 수 있기 때문입니다. 아직 보내지 않았다는 것을 사용자에게 확인한 경우에만 `--force`로 다시 만듭니다.
- 회신을 받은 뒤에 추가로 물어볼 것이 생기면 기존 파일을 고치지 않고, 새 작성일로 질문지를 하나 더 만듭니다.

### 2.5 통합 문서에 질문 현황 기록

질문지를 만든 뒤에는, 통합 문서를 읽는 사람이 어떤 사항이 인계자에게 문의 중인지 알 수 있도록 다음을 기록합니다.

- **`## 인수인계 확인 사항`**: `- **인계자 확인 요청**: 질문지 261012 · Q-001 ~ Q-024 (회신 대기)` 항목을 추가합니다.
- **본문의 `확인 필요` 표시**: 질문으로 넣은 부분에는 `확인 필요 (질문지 261012 · Q-001)`과 같이 질문 번호를 덧붙여서, 답변이 오면 어디를 채워야 하는지 알 수 있게 합니다.
- **`## 질문지 현황` 섹션**: `원본 파일 대응표` 뒤, `인수인계 확인 사항` 앞에 아래 표를 둡니다.

```markdown
## 질문지 현황

| 질문지 파일 | 작성일 | 질문 수 | 회신일 | 답변 수 | 미회신 | 상태 |
| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| `261012 조호재 업무인계인수 질문지.xlsx` | 2026-10-12 | 24 | - | - | - | 회신 대기 |
```

- **마스터 허브(`handover/index.md`)**: 해당 건의 `상태`를 `질문지 회신 대기`로 바꿉니다.
- 이 기록은 문서의 실질적인 내용 변경이 아니므로, 최종 수정일과 홈의 최근 업데이트 표는 갱신하지 않습니다. 빌드 검증은 수행합니다.

### 2.6 사용자에게 보고하고 멈춤

다음을 보고한 뒤 작업을 멈추고 회신을 기다립니다.

- 질문지 파일의 경로, 질문 수(중요도별), 업무 분야별 질문 수
- 중요도 '상' 질문의 목록
- 안내: 파일을 열어 질문을 검토하고, 필요하면 질문을 고치거나 표 아래에 행을 추가한 뒤 인계자에게 전달합니다. 답변이 적힌 파일을 회신받으면 `3. 업무인수인계 질문지/` 폴더에 넣고 "질문지 답변 왔어"라고 요청합니다. 회신 파일은 원래 파일을 덮어써도 되고 다른 이름으로 넣어도 됩니다.

## 3. 4단계: 답변 반영

### 3.1 회신 파일 확인

```bash
.venv/bin/python .agents/skills/handover-questionnaire/scripts/questionnaire.py list
.venv/bin/python .agents/skills/handover-questionnaire/scripts/questionnaire.py read \
  "3. 업무인수인계 질문지/261012 조호재 업무인계인수 질문지.xlsx" \
  --json "2. 변환 중간본/질문지/2024-cho-hojae-답변.json"
```

- `list`는 폴더의 파일별 질문 수, 답변 수, 미회신 수, 수정 시각을 보여 줍니다. 같은 질문지의 사본이 여러 개이면(보낸 파일과 회신 파일을 다른 이름으로 둔 경우) 답변이 적힌 파일 가운데 수정 시각이 가장 늦은 것을 회신 파일로 보고, 어느 파일을 사용했는지 사용자에게 알립니다. 작성일이 다른 질문지(추가 질문지)는 서로 다른 질문지이므로 각각 읽습니다.
- `read`가 만드는 JSON의 `questions`에는 질문별로 `id`, `question`, `answer`, `note`, `doc`, `answered`가 들어 있습니다. 번호가 없는 행(사용자나 인계자가 표 아래에 추가한 행)은 `추가-1`, `추가-2`로 읽습니다.
- 답변이 하나도 없으면 문서를 고치지 않고, 회신 파일이 폴더에 들어 있는지 사용자에게 확인을 요청합니다.
- `read`가 실패하면(인계자가 `.xls`나 한글 문서로 회신한 경우 등) kordoc으로 해당 파일을 변환해 내용을 확인한 뒤 같은 규칙으로 반영합니다. 이 때문에 사용자에게 파일 형식을 바꿔 달라고 요청하지 않습니다.

### 3.2 답변을 문서에 반영하는 규칙

답변은 인계자가 직접 쓴 글이므로 원본 자료와 같은 수준의 근거로 취급합니다. 답변의 내용은 **통합 문서의 해당 절에 녹여 넣어 문서를 완성**하고, 질문과 답변의 원문은 따로 남깁니다. 표기 형식은 `mkdocs-writing-guide` 4.3절을 따릅니다.

- **반영할 위치**: 질문의 `반영 문서`(`doc`)에 적힌 절과 `관련 내용`이 가리키는 부분입니다. 답변의 내용이 다른 절에 더 알맞으면 그 절에 반영합니다.
- **본문에 녹여 넣습니다**: 답변의 내용으로 `확인 필요` 칸, 빠진 절차 단계, 담당·연락처, 일정을 채우고, 필요하면 표와 다이어그램도 고친 뒤 출처 표기를 붙입니다. 답변으로 새 업무나 주의 사항이 드러나면 알맞은 절을 새로 만들어 넣습니다.
- **답변의 내용을 생략하지 않습니다.** 답변에 적힌 설명, 단서, 예외를 모두 본문에 반영하며, 답변의 뜻을 추측해서 보태지 않습니다.
- **원문을 따로 남깁니다**: `## 인계자 보충 답변` 섹션에 질문과 답변을 질문지에 적힌 문장 그대로 옮깁니다. 명백한 오탈자도 고치지 않습니다. `추가-N` 행도 같은 방식으로 반영합니다.
- **"모름"이라는 답변**은 본문의 `확인 필요`를 그대로 두고, `**미결 사항**`에 "인계자도 알지 못함(질문지 261012 · Q-005)"과 같이 적어서, 다른 경로로 확인해야 한다는 점을 남깁니다.
- **"해당 없음"이라는 답변**은 본문의 `확인 필요`를 `해당 없음`으로 바꾸고 출처 표기를 붙입니다.
- **답변이 자료와 다른 경우**: 답변이 최신 기준이라고 명시되어 있으면 본문을 답변에 맞추고, 자료에 적혀 있던 값과 달라졌다는 점을 그 자리에 함께 적습니다. 어느 쪽이 맞는지 알 수 없으면 두 값을 모두 적고 `**미결 사항**`에 넣습니다.
- **함께 갱신할 곳**: `## 요약` 표의 `**질문지 반영**` 행과 답변으로 달라진 행(`**먼저 할 일**` 등), `## 인수인계 확인 사항`(해결된 미결 사항은 지우거나 고쳐 쓰고, `**인계자 확인 요청**`은 미회신 질문만 남기며, 모두 회신되었으면 항목을 지움), 최종 수정일입니다.

### 3.3 미회신 질문과 추가 질문

- 답변이 비어 있는 질문은 `**인계자 확인 요청**` 항목에 `(미회신)`으로 남기고, `## 질문지 현황` 표 아래에 미회신 질문 목록(번호, 질문, 관련 절)을 표로 적습니다. 본문의 `확인 필요 (질문지 261012 · Q-007)` 표시는 그대로 둡니다.
- 인계자가 나중에 나머지 답변을 채워 다시 회신하면 같은 절차를 반복합니다. 이미 반영한 질문은 `## 인계자 보충 답변`의 블록 제목(`질문지 YYMMDD · Q-NNN`)을 검색해서 구별하고, 새로 채워진 답변만 반영합니다. 이미 반영한 답변의 내용이 바뀌었으면 본문과 블록을 새 답변으로 고칩니다.
- 답변을 읽고 새로 생긴 의문은 사용자에게 목록으로 보고합니다. 사용자가 요청하면 2.4절에 따라 새 작성일로 질문지를 하나 더 만듭니다.

### 3.4 인계자가 자료를 추가로 보낸 경우

- 답변에 언급된 추가 파일을 사용자가 `1. RAW/`의 해당 건 폴더에 넣었다면, `handover-to-mkdocs` 5절(증분 갱신)에 따라 변환하고 문서에 반영합니다.
- 답변에 파일명이 적혀 있는데 `1. RAW/`와 `3. 업무인수인계 질문지/`에서 그 파일을 찾을 수 없으면, 사용자에게 파일을 받았는지 확인을 요청합니다. 이 때문에 나머지 답변의 반영을 멈추지 않습니다.

### 3.5 현황 갱신과 검증

- **통합 문서**: `## 질문지 현황` 표의 `회신일`(회신 파일의 수정일), `답변 수`, `미회신`, `상태`(`보강 완료` 또는 `일부 미회신`)를 갱신합니다.
- **마스터 허브**: 해당 건의 `상태`를 `보강 완료` 또는 `일부 미회신`으로 바꿉니다.
- **홈**: 답변 반영은 실질적인 내용 변경이므로, 최근 업데이트 표에서 해당 건의 날짜를 갱신합니다.
- 빌드 검증과 화면 검증은 `mkdocs-writing-guide` 6·7절을 따릅니다. 답변으로 고친 표·다이어그램과 `## 인계자 보충 답변` 섹션을 브라우저로 확인합니다.
- 사용자에게 반영한 답변 수, 고친 절의 목록, 미회신 질문, 새로 생긴 의문을 보고합니다.

## 4. 완료 조건

### 3단계 (질문지 작성)

- [ ] 질문마다 중간본 전체를 검색해서, 자료에 답이 없는 사항만 남겼다.
- [ ] 질문마다 업무 분야, 관련 자료, 관련 내용, 질문 유형, 중요도, 반영 문서가 적혀 있다(특정 자료에 근거하지 않는 질문은 관련 자료·관련 내용 생략).
- [ ] `3. 업무인수인계 질문지/YYMMDD <인계자명> 업무인계인수 질문지.xlsx`가 만들어졌고, 기존 파일을 덮어쓰지 않았다.
- [ ] 통합 문서의 `확인 필요` 표시에 질문 번호를 붙였고, `인수인계 확인 사항`, `질문지 현황`, 마스터 허브의 `상태`를 기록했으며 빌드 검증이 통과했다.
- [ ] 질문지 경로와 질문 수, 인계자에게 전달하고 회신받은 뒤에 할 일을 사용자에게 안내했다.

### 4단계 (답변 반영)

- [ ] 회신 파일의 답변이 적힌 질문이 모두 통합 문서의 해당 절에 반영되었고, 답변의 내용을 생략하지 않았으며, 반영한 부분에 `질문지 YYMMDD · Q-NNN` 출처가 붙어 있다.
- [ ] `## 인계자 보충 답변` 섹션에 질문과 답변이 질문지에 적힌 문장 그대로 남아 있다.
- [ ] `요약` 표(`질문지 반영` 행), `인수인계 확인 사항`, 최종 수정일을 갱신했다.
- [ ] 미회신 질문이 `인계자 확인 요청`과 `질문지 현황`에 남아 있다.
- [ ] `질문지 현황`, 마스터 허브의 `상태`, 홈의 최근 업데이트를 갱신했고 빌드 검증이 통과했다.
- [ ] `1. RAW/`의 파일과 `3. 업무인수인계 질문지/`의 기존 파일은 하나도 바뀌지 않았다.
